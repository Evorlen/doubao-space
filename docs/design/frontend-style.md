# 豆包空间前端设计与开发规范

## 1. 文档信息

- 版本：v1.0
- 状态：初版规范
- 适用范围：所有 Vue 页面、组件、交互和前端代码
- 产品形态：面向桌面端的单用户本地个人工作台

本文档规定豆包空间的视觉基线、页面结构、交互状态和前端实现约定。后续新页面应优先复用本文档中的设计令牌和组件规则；确实需要新增模式时，应先补充规范，再实现页面。

## 2. 产品气质

豆包空间的界面应给人以下感受：

- 安静：降低视觉噪音，让用户可以持续处理自己的事情；
- 清晰：通过层级、间距和状态表达信息关系；
- 可靠：重要操作有明确反馈，数据状态和错误原因透明；
- 轻巧：保留个人工具的亲近感，不做企业后台式的复杂装饰；
- 温和：使用偏暖的点缀色表达鼓励，但不依赖高饱和色吸引注意。

核心原则：内容优先、状态明确、操作可预期、局部有温度。

## 3. 页面与信息架构

### 3.1 应用框架

统一使用“左侧主导航 + 右侧工作区”的应用框架：

- 左侧导航宽度默认 `220px`，承载品牌、一级导航和简短的产品信息；
- 右侧工作区包含页面标题区和页面主体；
- 页面主体不嵌套第二个固定侧栏，任务模块使用全宽任务树；
- 页面之间通过路由切换，详情页使用独立路由；
- 全局弹窗只承载短流程，完整编辑使用独立页面。

一级导航顺序固定为：工作台、任务、豆包、日历、个人计划、娱乐、设置。没有实现的模块可以暂时隐藏，不展示无实际功能的导航入口。

### 3.2 页面类型

页面按以下五种类型组织：

1. 概览页：展示摘要、快捷入口和状态，例如工作台；
2. 列表/树页面：承载任务、收集内容等高频管理场景；
3. 详情页：展示单个对象的完整信息，并支持编辑；
4. 时间页面：承载日历、日期和提醒相关内容；
5. 设置页：按主题分组展示偏好和数据管理选项。

每个页面只保留一个主要目标。页面标题区应包含标题，必要时包含一句说明和一组页面级操作。

### 3.3 内容宽度

- 普通页面最大内容宽度：`1200px`；
- 任务树、日历等信息密度较高的页面最大内容宽度：`1440px`；
- 页面左右内边距：大桌面 `40px`，窄桌面 `24px`；
- 页面顶部标题区与主体之间保持 `24px` 间距；
- 不用空白卡片强行填满页面，空状态应直接说明下一步操作。

## 4. 视觉设计令牌

所有颜色、间距、圆角和阴影优先通过 CSS 变量引用，不在业务组件中随意写新的色值。

### 4.1 色彩

```css
:root {
  --ds-color-brand-900: #1f2a44;
  --ds-color-brand-800: #334363;
  --ds-color-brand-700: #415987;
  --ds-color-primary: #526b9b;
  --ds-color-primary-hover: #415987;
  --ds-color-primary-light: #edf1fa;

  --ds-color-accent: #f7c873;
  --ds-color-canvas: #f5f7fb;
  --ds-color-surface: #ffffff;
  --ds-color-surface-muted: #f8f9fc;
  --ds-color-border: #e5e9f2;
  --ds-color-border-strong: #d3daea;

  --ds-color-text-primary: #253047;
  --ds-color-text-secondary: #56627a;
  --ds-color-text-tertiary: #8490a7;
  --ds-color-text-disabled: #b4bdce;
  --ds-color-text-on-brand: #ffffff;

  --ds-color-success: #67c23a;
  --ds-color-warning: #e6a23c;
  --ds-color-danger: #f56c6c;
  --ds-color-info: #909399;
}
```

使用规则：

- 深蓝用于导航、标题和品牌层级；
- 主色用于主要按钮、链接、选中态和可交互强调；
- 金黄色只用于品牌点缀、少量提醒和积极反馈，不作为大面积背景；
- 红色只表示危险、错误或逾期，不表示普通强调；
- 状态不能只靠颜色区分，应同时配合文字、图标或形状；
- 默认页面背景为 `--ds-color-canvas`，内容容器为白色；
- 新增颜色必须说明语义，并补充到令牌中。

### 4.2 字体

```css
:root {
  --ds-font-family: Inter, -apple-system, BlinkMacSystemFont,
    "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif;
}
```

字体层级：

| 用途 | 字号/行高 | 规则 |
| --- | --- | --- |
| 页面标题 | `28px / 36px` | 600，单行优先 |
| 大型页面标题 | `32px / 40px` | 600，仅用于欢迎区等场景 |
| 区块标题 | `18px / 26px` | 600 |
| 正文 | `14px / 22px` | 默认内容文字 |
| 辅助文字 | `13px / 20px` | 说明、统计标签 |
| 注释 | `12px / 18px` | 时间、帮助信息、次要状态 |
| 数据数字 | `28px / 36px` | 使用 `font-variant-numeric: tabular-nums` |

中文是主要内容语言。英文只用于品牌标识、技术信息或非常短的装饰性眉标题，不得让用户为了理解功能而阅读英文。

### 4.3 间距

以 `4px` 为基础单位，只使用以下间距：

```text
4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64
```

常用约定：

- 表单控件之间：`16px`；
- 卡片内边距：`20px` 或 `24px`；
- 页面区块之间：`20px` 或 `24px`；
- 页面标题与说明之间：`8px`；
- 图标与文字之间：`8px`；
- 紧密排列的标签之间：`6px`。

### 4.4 圆角和阴影

```css
:root {
  --ds-radius-sm: 6px;
  --ds-radius-md: 10px;
  --ds-radius-lg: 15px;
  --ds-radius-xl: 18px;
  --ds-radius-pill: 999px;

  --ds-shadow-card: 0 4px 16px rgba(37, 48, 71, 0.06);
  --ds-shadow-float: 0 12px 32px rgba(37, 48, 71, 0.14);
  --ds-shadow-hero: 0 16px 35px rgba(45, 64, 105, 0.16);
}
```

- 普通卡片默认无明显阴影，使用边界和留白分组；
- 浮层、下拉菜单和弹窗使用 `--ds-shadow-float`；
- 欢迎区等特殊视觉模块可以使用 `--ds-shadow-hero`；
- 不给每一个按钮、列表行和标签添加阴影；
- 输入框、卡片和按钮的圆角应有层级，不全部使用同一个值。

## 5. 布局规范

### 5.1 导航栏

- 背景使用 `--ds-color-brand-900`；
- 品牌标识位于顶部，包含图形标记、产品名和简短副标题；
- 一级菜单高度约 `44–46px`，菜单项之间保留 `4px`；
- 默认文字使用低饱和浅蓝灰；
- 悬停和激活态使用 `--ds-color-brand-800`，激活文字为白色；
- 导航图标统一使用线性图标，图标与文字间距 `10px`；
- 底部只显示一句低干扰的产品属性信息。

### 5.2 页面标题区

页面标题区结构固定为：眉标题（可选）→ 页面标题 → 说明（可选）→ 页面操作。

- 页面标题使用深色，不使用渐变文字；
- 页面操作放在标题区右侧；
- 主要操作最多一个，其他操作使用次级按钮或更多菜单；
- 操作按钮在窄窗口下允许换行，但不能遮挡标题；
- 不用重复显示当前导航名称和页面标题。

### 5.3 卡片

卡片用于表达一个相对独立的信息区块，而不是包裹所有内容。

- 默认背景白色，边界为 `--ds-color-border` 或无边界；
- 标题、内容和操作按垂直层级排列；
- 卡片标题行高度不低于 `24px`；
- 卡片内不再嵌套超过一层卡片；
- 可点击卡片必须提供悬停、键盘聚焦和按下反馈。

### 5.4 列表和树

- 行高按内容密度选择 `48px`、`56px` 或 `64px`；
- 行悬停使用很浅的主色背景；
- 选中态同时提供背景和边界/文字变化；
- 操作入口固定在行尾，使用图标按钮或“更多”菜单；
- 完成、禁用和归档内容降低文字对比度，但仍需满足可读性；
- 任务树缩进每层使用固定间距，最多展示到设计允许的层级；
- 不用拖拽作为任务层级调整的默认交互。

## 6. 组件规范

### 6.1 按钮

按钮按语义分为：

- 主要按钮：页面最重要的提交或创建动作；
- 次级按钮：普通操作；
- 文本按钮：低干扰的辅助动作；
- 危险按钮：删除、永久清除等不可逆动作；
- 图标按钮：仅适用于用户熟悉的单一动作，必须提供 `aria-label` 或可见提示。

规则：

- 一个页面或弹窗最多一个主要按钮；
- 按钮文字使用“动词 + 对象”，例如“新建任务”“保存修改”；
- 保存按钮在提交中显示加载状态并暂时禁用；
- 破坏性按钮默认不与主要按钮使用同样的视觉权重；
- 不使用 Emoji 代替功能图标。

### 6.2 表单

- 标签默认置于控件上方；
- 必填字段使用统一的红色星号，并在表单说明中解释；
- 字段顺序按照用户完成任务的自然顺序排列；
- 帮助文案放在控件下方，错误文案紧邻出错控件；
- 校验失败时保留用户输入，不清空表单；
- 错误提示应说明原因和下一步动作；
- 日期时间格式统一为 `YYYY-MM-DD HH:mm`；
- 禁用字段必须同时解释禁用原因，不能只降低透明度；
- 编辑页面需要处理未保存离开提示。

### 6.3 弹窗和抽屉

- 完整任务编辑使用独立详情页；
- 新建任务等短流程使用大尺寸弹窗，建议宽度 `720–880px`；
- 删除确认弹窗建议宽度 `420–480px`；
- 弹窗标题说明当前对象和动作；
- 底部操作顺序为“取消”在左、“确认/保存”在右；
- 关闭弹窗前检查未保存内容；
- 不使用右侧抽屉承载完整详情页。

### 6.4 标签、徽章和状态

- 标签用于分类，不用于表达操作；
- 状态徽章使用短文本，避免一枚徽章中塞入句子；
- 标签过多时优先显示前几个，剩余数量用 `+N` 表示；
- 优先级、完成状态和逾期状态使用固定语义，不随页面改变颜色含义；
- 逾期只突出截止时间，不把整个任务行染成红色。

### 6.5 图标

- 功能图标统一使用同一套线性图标；
- 常规尺寸为 `16px`、`18px`、`20px`；
- 图标不能单独承担关键含义，必要时配合文字；
- `✦` 等装饰字符只能用于品牌或空状态装饰，不能代替保存、删除等操作图标；
- 图标按钮的可点击区域不小于 `36px × 36px`。

## 7. 交互和状态规范

每个页面和组件都必须考虑以下状态：初始、加载、成功、有数据的正常状态、空状态、错误、禁用、未保存和权限/规则阻止状态。

### 7.1 加载

- 首屏或大块内容使用骨架屏；
- 按钮提交使用按钮内加载指示，不让页面整体闪烁；
- 局部刷新不覆盖用户正在查看的其他内容；
- 长时间请求应提供明确的失败反馈。

### 7.2 空状态

空状态包含三部分：当前没有什么、为什么没有、用户可以做什么。

示例结构：

```text
还没有任务
把想做的事情记录下来，再逐步拆解。
[新建任务]
```

空状态插画或装饰保持轻量，不使用大型复杂插画抢占注意力。

### 7.3 成功和错误反馈

- 保存成功：使用短暂的成功提示，并更新页面数据；
- 校验错误：显示在字段附近；
- 业务规则阻止：使用明确的阻止弹窗或页面提示，列出冲突对象；
- 网络或服务错误：说明请求失败，并提供“重试”；
- 不用只显示“操作失败”这类无法行动的文案。

### 7.4 危险操作

删除、永久清除、不可恢复的状态变更必须二次确认。确认文案应包含：

1. 将要发生什么；
2. 影响哪些对象；
3. 是否可以恢复；
4. 用户需要点击什么才能继续。

### 7.5 动效

- 普通状态切换：`120–180ms`；
- 弹窗、菜单和页面区块：`180–240ms`；
- 使用平滑、克制的缓动，不做持续跳动和无意义循环动画；
- 页面加载不使用大面积渐变闪烁；
- 支持 `prefers-reduced-motion`，用户关闭动效后应减少或移除过渡。

## 8. 响应式规则

豆包空间 v1 以桌面端为主要目标，最低设计宽度为 `1024px`。

- `>= 1440px`：侧栏 `220px`，页面主体可使用 `40px` 外边距；
- `1024–1439px`：侧栏保持可用，页面主体外边距收窄到 `24px`；
- 卡片栅格从三列逐步收缩为两列或一列；
- 任务树、表格和日历优先保证关键列可读，不为了强行压缩而使用过小字号；
- 窄桌面下页面级操作可以换行或收纳到更多菜单；
- 当前版本不设计手机端专属导航，后续如支持移动端应另行增加断点和交互方案。

## 9. 文案和格式规范

- 产品界面统一使用简体中文；
- 文案简短、具体、可执行；
- 按钮使用动词，不使用“确定一下”“好的”等模糊表述；
- 错误文案使用“发生了什么 + 如何处理”的结构；
- 中文界面使用中文标点；
- 日期时间统一显示为 `2026-09-25 18:00`；
- 数量为零时显示 `0`，不使用空白代替；
- 删除、完成、移动等不可逆或有约束的动作，文案必须明确影响范围；
- 所有用户可见文本不得散落在模板之外的随机常量中，重复文案应集中管理。

## 10. Vue 和 Element Plus 实现约定

### 10.1 目录职责

```text
web/frontend/src/
├── api/              请求模块和接口适配
├── assets/           图片、字体等静态资源
├── components/       可复用业务组件
│   └── ui/           通用界面组件
├── composables/      可复用的组合式逻辑
├── layouts/          页面级布局
├── router/           路由定义
├── styles/           设计令牌、全局样式、Element Plus 覆盖
├── views/            路由页面
└── App.vue
```

当前项目可以继续使用 JavaScript 和 `<script setup>`；不要在单个功能开发中混入不完整的 TypeScript 迁移。业务请求不直接写在模板中，页面通过 `api/` 模块和 `composables/` 组合逻辑使用数据。

### 10.2 组件约定

- 组件名使用 PascalCase，例如 `TaskTree.vue`；
- 页面组件只负责页面编排，复杂业务逻辑放入 composable 或领域模块；
- 子组件通过 props 接收数据，通过 emits 通知变化，不直接修改 props；
- 异步组件必须明确暴露 `loading`、`error` 和重试能力；
- 通用组件不依赖具体页面路由；
- 页面内样式优先使用 `scoped`，全局规则只放在 `styles/`；
- Element Plus 的主题覆盖集中管理，不在多个页面重复覆盖同一个选择器。

### 10.3 样式约定

- 颜色和间距必须优先使用 `--ds-*` 变量；
- CSS 类名使用小写 kebab-case，复杂组件采用 block-element-modifier 形式，例如 `.task-tree__row.is-complete`；
- 不使用行内样式表达长期设计规则；
- 不在组件中直接复制 Element Plus 的默认颜色；
- 不使用 `!important` 解决常规层级问题，确需覆盖时集中记录原因；
- 不以深层选择器大范围修改第三方组件，优先使用主题变量或包装组件。

### 10.4 路由约定

- 路由名称使用稳定的英文语义名，页面标题放在 `meta.title`；
- 页面级权限、导航高亮和面包屑信息放在路由元数据中；
- 详情页使用对象 ID 路由，不通过全局变量保存当前对象；
- 离开编辑页前统一执行未保存变更检查；
- 路由懒加载页面组件，避免首屏加载全部功能。

## 11. 可访问性

- 正文和交互文字满足 WCAG AA 对比度要求；
- 键盘可以访问所有主要操作；
- 使用 `:focus-visible` 提供清晰焦点环；
- 图标按钮必须有 `aria-label`，表单控件必须与标签关联；
- 弹窗打开后将焦点放入弹窗，关闭后恢复到触发控件；
- 状态、错误和成功反馈使用适当的 `aria-live`；
- 不仅依靠颜色区分完成、逾期、错误和选中状态；
- 文本可在系统放大后保持可读，不能依赖固定高度裁切关键内容。

## 12. 页面验收清单

新增页面完成前，至少检查：

- 是否符合应用框架和内容宽度规则；
- 是否只使用设计令牌中的颜色、间距、圆角和阴影；
- 是否有正常、加载、空、错误和禁用状态；
- 主要操作是否唯一且文案明确；
- 表单错误是否靠近字段并保留用户输入；
- 危险操作是否二次确认；
- 键盘焦点、图标按钮标签和弹窗焦点是否完整；
- `1024px` 和宽桌面窗口下是否都能正常使用；
- 是否没有把业务请求、复杂计算和大量文本直接堆在页面模板中；
- 是否执行了 `npm run build`，并检查无控制台错误。

## 13. 与现有界面的衔接

当前已经存在的深蓝侧栏、浅灰工作区、蓝色欢迎区、黄色品牌点缀和卡片式工作台，作为本规范 v1 的视觉基线继续保留。

后续实现时需要逐步补齐：

1. 将现有散落色值收敛到 `--ds-*` 设计令牌；
2. 把一级导航补充为实际已实现的功能集合；
3. 统一 Element Plus 按钮、输入框、弹窗、标签和菜单的主题；
4. 为任务树、任务详情、日历、个人计划和娱乐分别建立可复用页面组件；
5. 按本文档补充加载、空状态、错误、确认和无障碍处理。
