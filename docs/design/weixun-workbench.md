# 唯寻工作台设计

## 1. 文档信息

- 状态：构思中，第一版讨论稿
- 版本：v0.1
- 适用范围：唯寻教育相关的学生、课程、考试和跟进工作
- 当前原则：先确定业务对象和工作流程，再实现页面和数据库
- 当前产品基线：豆包空间目前是单用户、本地 SQLite 应用；唯寻工作台是否继续沿用这一基线，需要单独确认

这是一份会持续更新的产品文档。后续讨论中确认的内容应沉淀到“已确认决策”部分；尚未确认的内容保留在“待确认问题”部分，不提前固化到代码和数据库。

## 2. 模块定位

唯寻工作台是豆包空间中面向教育业务的独立工作区，用于集中管理学生和围绕学生展开的课程、考试、目标和跟进事项。

它解决的核心问题是：

- 快速了解每位学生当前处于什么阶段；
- 清楚知道学生接下来要上什么课、参加什么考试、完成什么材料；
- 记录课程和考试结果，让后续安排有依据；
- 让老师或顾问能从一个工作台发现即将到期、缺少结果或需要跟进的事项；
- 保留学生的长期过程记录，减少信息分散在表格、聊天记录和个人笔记中的情况。

唯寻工作台与现有模块的关系：

| 现有模块 | 负责内容 | 与唯寻工作台的关系 |
| --- | --- | --- |
| 工作台首页 | 个人整体待办和近期信息 | 可展示唯寻工作台入口或摘要，不替代业务工作台 |
| 任务 | 通用任务树和截止时间 | 唯寻业务对象产生的跟进事项可关联任务 |
| 日历 | 日期和事件的统一呈现 | 课程、考试和预约可以提供日历事件 |
| 个人计划 | 周期性个人提醒 | 暂不作为学生业务计划的主要载体 |
| 备忘录 | 通用长文本记录 | 学生跟进记录应优先使用结构化记录，必要时关联备忘录 |

唯寻工作台内部应保持自己的业务上下文。学生、课程和考试不应被建模成普通任务或普通备忘录，否则后续统计、查找和权限控制会变得困难。

## 3. 设计目标

### 3.1 第一阶段目标

- 建立统一的学生档案和学生列表；
- 记录学生的教育阶段、目标方向、负责人员和当前状态；
- 管理课程安排、课程进度和课程结果；
- 管理考试计划、考试场次、成绩和目标差距；
- 在工作台首页聚合近期课程、考试、跟进事项和异常提醒；
- 支持搜索、筛选、排序和基础导入导出；
- 让每项业务记录都能追溯到对应学生。

### 3.2 后续目标

- 支持学生成长过程和阶段性里程碑；
- 支持目标学校、申请批次和材料准备；
- 支持学生、教师、顾问、管理人员的角色权限；
- 支持多位老师共同维护同一学生；
- 支持统计报表和阶段复盘；
- 根据实际业务决定是否连接外部教务系统、日历或消息渠道。

### 3.3 暂不默认纳入

以下内容先不作为第一阶段的默认范围：

- 计费、合同、收款和财务核算；
- 招生线索和销售漏斗；
- 完整的在线课堂、直播和作业批改；
- 自动读取第三方考试网站成绩；
- 自动向学生或家长发送短信、邮件和即时消息；
- 复杂的组织架构、跨校区权限和审批流；
- 用模型自动评价学生或自动决定课程安排。

这些内容可能属于唯寻教育的业务范围，但是否纳入本工作台要根据实际使用场景和数据来源逐项确定。

## 4. 使用角色

以下是第一版需要讨论的候选角色，不代表已经确定的权限设计。

| 角色 | 可能的主要工作 | 需要确认的问题 |
| --- | --- | --- |
| 教师 | 查看负责学生、维护课程、记录课堂结果和作业情况 | 是否需要看到完整学生档案和考试信息 |
| 顾问/规划老师 | 维护学生目标、考试计划、申请或升学节点 | 是否与教师共同维护同一学生 |
| 教务人员 | 安排课程和考试、维护基础数据、跟进缺失记录 | 是否可以修改教师录入的结果 |
| 管理人员 | 查看全局数据、分配负责人、查看报表 | 是否需要跨团队和跨校区汇总 |
| 学生 | 查看自己的课程、考试和阶段记录 | 第一阶段是否只做内部工作台，不开放学生端 |
| 家长 | 查看或接收学生进度 | 是否需要独立账号和独立可见字段 |

当前最关键的产品决策是：唯寻工作台是给一位内部工作人员使用的本地工具，还是将来要支持多个工作人员登录和协作。这个决定会影响数据库字段、权限、审计和部署方式，应在实现前确认。

## 5. 核心业务对象

### 5.1 学生

学生是唯寻工作台的中心对象，所有课程、考试和跟进记录都必须能关联到学生。

建议的第一版字段：

| 字段 | 说明 |
| --- | --- |
| 姓名 | 必填 |
| 英文名 | 可选 |
| 学生编号 | 可选但建议支持，后续用于导入和查重 |
| 性别 | 是否需要由实际业务确认 |
| 出生日期 | 涉及敏感信息，确认确有需要后再保存 |
| 当前教育阶段 | 例如初中、高中、本科或其他业务定义 |
| 所在学校 | 可选 |
| 所在年级 | 可选 |
| 目标地区/方向 | 先保留为结构化字段或标签，具体枚举待确认 |
| 目标学校 | 第一阶段可先用文本，后续再建立学校库 |
| 负责顾问 | 需要多用户后才有完整意义 |
| 负责教师 | 可多选还是单选，需要确认 |
| 学生状态 | 例如咨询中、服务中、已完成、暂停、归档，枚举待确认 |
| 入学/签约日期 | 是否属于本模块范围，需要确认 |
| 备注 | 用于不能结构化的补充信息，避免承载全部业务记录 |

学生详情页建议按时间和业务主题组织，而不是把所有字段放在一个长表单里：

```text
学生基本信息
├── 当前目标和阶段
├── 待处理事项
├── 课程记录
├── 考试记录
├── 里程碑与申请节点
├── 跟进记录
└── 文件和导出
```

### 5.2 课程

第一版先区分“课程定义”和“学生课程安排”：

- 课程定义：课程名称、科目、级别、默认时长、默认老师等可复用信息；
- 学生课程安排：某位学生在某个时间上某门课，由谁负责，当前状态和结果是什么。

学生课程安排建议支持：

- 学生；
- 课程名称或课程定义；
- 教师；
- 上课日期和时间；
- 课程时长；
- 课程状态：待上课、已完成、取消、改期，枚举待确认；
- 本节课主题；
- 课堂记录；
- 作业或课后任务；
- 下次课建议；
- 关联任务和附件。

第一版不必立即实现完整排课系统。可以先支持手动创建一条学生课程安排，并把日期同步到日历；重复排课、教室资源和老师冲突检测在排课需求明确后再做。

### 5.3 考试

“考试”建议拆成三个层次，避免把考试名称、一次考试和成绩混为一个字段：

1. 考试类型：例如雅思、托福、SAT、ACT、AP 或机构自定义考试；
2. 考试场次：某位学生计划参加或已经参加的一次考试，有考试日期和状态；
3. 成绩记录：该场考试的总分、分项成绩、目标分和成绩单文件。

考试场次建议支持：

- 学生；
- 考试类型；
- 考试日期；
- 报名或准备状态；
- 是否已参加；
- 成绩是否已出；
- 总分和分项成绩；
- 目标分；
- 与目标的差距；
- 备注和成绩单附件。

考试分项成绩不能在第一版写死成固定列。不同考试的科目和计分方式不同，建议先确认以下两种方案之一：

- 方案 A：第一阶段只保存总分，分项成绩放在 JSON 或备注中；
- 方案 B：建立“考试类型—分项”配置，成绩记录按分项保存。

如果唯寻日常工作高度依赖分项成绩，优先选择方案 B；如果第一阶段重点是学生和考试时间管理，可以先选择方案 A，避免过早设计复杂成绩模型。

### 5.4 跟进记录

跟进记录用于保存一次与学生有关的工作动作或沟通结果，例如电话、家长沟通、阶段复盘或资料提醒。

建议字段：

- 学生；
- 记录时间；
- 记录人；
- 跟进类型；
- 内容；
- 下一步；
- 下一步截止时间；
- 是否需要继续跟进；
- 关联任务、课程或考试。

跟进记录与备忘录的区别是：跟进记录必须属于某位学生，并且可以形成下一步工作；备忘录适合存放不属于单一学生的长期内容。

### 5.5 里程碑

里程碑用于表达学生阶段变化，而不是普通的待办事项。候选里程碑包括：

- 确定目标方向；
- 完成某阶段课程；
- 达到某项考试目标分；
- 完成一次阶段评估；
- 完成申请材料；
- 获得录取或完成项目。

第一阶段可以只把里程碑作为学生的时间线记录；当流程稳定后，再将其做成可配置的阶段模板。

### 5.6 文件

可能涉及学生证件、成绩单、作业、课程材料和申请文件。文件属于敏感数据，第一阶段需要先确认：

- 是否确实要在本系统保存原文件；
- 是否只保存外部文件链接；
- 文件是否需要分类、到期提醒和下载权限；
- 本地备份是否满足实际要求。

在这些问题确认前，不把文件上传作为首个开发目标。

## 6. 工作台首页草案

唯寻工作台首页应该回答“今天需要关注什么”和“哪些学生正在偏离计划”，不只是展示总数。

建议的首版区域：

### 6.1 今日工作

- 今日课程；
- 今日考试或考试提醒；
- 今天到期的学生跟进事项；
- 需要补录结果的课程或考试；
- 最近需要回复的学生记录。

### 6.2 学生概况

- 服务中学生总数；
- 近期新增学生；
- 近期没有更新记录的学生；
- 按阶段或负责人分布。

### 6.3 风险与提醒

- 考试日期临近但没有准备计划；
- 目标分与最近成绩存在差距；
- 连续缺课、取消或改期；
- 课程完成后缺少课堂记录；
- 跟进事项逾期。

这些提醒只在有明确数据规则后实现。第一版可以先展示事实数据，不自动给学生贴“风险”标签。

### 6.4 快速操作

- 新建学生；
- 安排课程；
- 添加考试；
- 记录成绩；
- 添加跟进记录；
- 导入学生或考试表格。

## 7. 页面结构草案

如果唯寻工作台作为一级模块，建议先使用独立路由和二级导航：

```text
唯寻工作台
├── 概览
├── 学生
├── 课程
├── 考试
├── 跟进
└── 设置
```

### 7.1 概览

展示今日工作、近期考试、待跟进学生和需要补录的数据。

### 7.2 学生

学生列表应支持：

- 姓名、学生编号和学校搜索；
- 状态、教育阶段、目标方向、负责人筛选；
- 最近更新排序；
- 批量导入和导出；
- 新建、归档和查看学生详情。

学生详情页是整个模块的主要工作页面，课程、考试、跟进和时间线都应能从这里进入。

### 7.3 课程

首版可以提供“课程安排列表 + 按日期查看”的组合：

- 按日期、学生、教师、状态筛选；
- 快速记录已完成课程；
- 补充课堂记录和作业；
- 跳转学生详情；
- 与日历事件关联。

### 7.4 考试

- 查看即将到来的考试；
- 按考试类型、学生和状态筛选；
- 录入或修改成绩；
- 查看目标分与最近成绩；
- 管理成绩单附件或外部链接。

### 7.5 跟进

- 按到期日查看跟进事项；
- 按学生、记录人和类型筛选；
- 完成跟进并填写结果；
- 从跟进记录创建通用任务。

## 8. 状态和规则草案

### 8.1 学生状态

候选状态：

- 待开始；
- 服务中；
- 暂停；
- 已完成；
- 已归档。

状态名称和状态变更规则需要结合唯寻实际业务确认。尤其要明确“已完成”和“已归档”的区别：前者表示服务目标结束，后者表示不再作为日常工作对象。

### 8.2 课程规则

候选规则：

- 已取消的课程不计入完成率；
- 已完成课程可以补录课堂记录，但修改应保留更新时间；
- 改期是否保留原始记录，还是直接修改日期，需要确认；
- 一节课程是否允许关联多个学生，需要确认；
- 一位教师是否可以同时被安排冲突课程，需要确认。

### 8.3 考试规则

候选规则：

- 同一学生可以有多次同类型考试；
- 计划考试和实际参加考试分开记录；
- 成绩未出不能被当作零分；
- 总分和分项成绩应保留原始记录；
- 目标分可以按考试场次设置，也可以按学生目标设置，需要确认；
- 成绩修改需要记录修改时间，是否需要修改人取决于权限模型。

### 8.4 跟进规则

- 逾期跟进不改变学生状态，只显示为逾期；
- 完成跟进时必须保留完成时间；
- 需要下一步时可以创建新的跟进或关联通用任务；
- 跟进记录是否允许删除，需要结合审计要求确认。

## 9. 数据和权限原则

学生信息、考试成绩和文件可能属于敏感数据。即使第一版继续作为本地单用户工具，也应从一开始遵循以下原则：

- 只保存业务确实需要的字段；
- 通过学生编号或内部 ID 关联数据，避免在各表重复保存姓名；
- 删除操作优先使用归档或软删除，避免误删学生历史记录；
- 对成绩、课程结果和跟进记录保留更新时间；
- 备份文件与数据库使用相同的数据目录保护策略；
- 文件和导出内容需要明确是否包含敏感字段；
- 如果未来支持多用户，再增加角色权限、操作审计和字段级可见性。

不应在尚未确定部署方式前，假设“本地文件路径”等信息可以安全地交给其他用户使用。

## 10. 数据导入与导出草案

由于教育机构通常已经有学生表、课程表或考试表，导入很可能是首批实际需求之一。但导入模板要在业务字段稳定后设计。

建议按对象分别提供模板：

- 学生导入模板；
- 课程安排导入模板；
- 考试计划导入模板；
- 成绩导入模板。

每个模板都应采用与任务和娱乐模块一致的“下载模板—上传预览—逐行校验—确认写入”流程，并明确：

- 哪些字段必填；
- 哪些字段使用枚举；
- 学生如何查重；
- 课程和考试如何关联学生；
- 错误行是否阻止整个批次；
- 导入后如何回滚或再次导入。

第一版建议先选择一种真实、频繁使用的表格作为导入对象，不同时设计所有模板。

## 11. 分阶段实施建议

### 阶段 0：业务确认

先确认以下内容：

- 实际使用者和角色；
- 是单人本地使用还是多人协作；
- 学生的最小必要字段；
- 唯寻日常最常用的考试类型；
- 课程是按单节安排还是按周期排课；
- 第一阶段最需要解决的一个工作痛点。

阶段 0 完成标准：能用一条完整流程描述“新增学生 → 安排课程或考试 → 记录结果 → 产生下一步工作”。

### 阶段 1：学生基础和详情

- 学生列表；
- 学生新建、编辑、归档；
- 学生详情页；
- 基础搜索和筛选；
- 学生时间线的最小版本。

### 阶段 2：课程和考试

- 学生课程安排；
- 课程状态和课堂记录；
- 考试计划；
- 考试成绩的最小结构；
- 与日历的只读关联或跳转。

### 阶段 3：工作台和跟进

- 今日工作区；
- 跟进记录；
- 逾期和缺失数据提醒；
- 从业务记录创建通用任务；
- 学生、课程、考试之间的关联导航。

### 阶段 4：批量操作和报表

- 选定对象的 Excel 导入；
- 常用报表；
- 数据导出；
- 课程完成、考试成绩和学生阶段的趋势统计。

### 阶段 5：协作和外部连接

- 多用户和角色权限；
- 操作审计；
- 外部教务或考试数据同步；
- 学生或家长端访问；
- 消息和提醒渠道。

## 12. 已确认决策

## 13. 待确认问题

建议按以下顺序逐步讨论：

### 第一组：使用边界

1. 唯寻工作台第一阶段主要给谁使用：教师、顾问、教务人员、管理者，还是只有你个人？
2. 是否需要多人同时使用和登录？如果暂时不需要，是否仍要预留负责人字段？
3. 当前最急需解决的是学生信息分散、课程安排、考试管理，还是跟进提醒？

### 第二组：学生和业务

4. 需要管理哪些教育阶段和项目？是否只面向国际教育相关学生？
5. 学生是否有稳定的内部编号？现有学生表能否提供这个编号？
6. 是否要记录家长、联系方式、合同或收费信息？这些信息的使用边界是什么？
7. 学生状态和阶段变化是否需要保留历史，而不是只保留当前值？

### 第三组：课程

8. 课程管理的基本单位是一节课、一个课程包，还是一个长期课程？
9. 是否需要教师、教室、课时、课后作业和出勤？
10. 课程是否需要重复排课和冲突检查？
11. 课堂记录是否需要固定模板，例如主题、问题、作业和下节课计划？

### 第四组：考试

12. 第一阶段最常用的考试有哪些？
13. 需要记录哪些分项成绩和成绩单位？
14. 目标分是按学生、考试类型还是每次考试设置？
15. 成绩单是上传到本地、保存外部链接，还是暂时不保存？

### 第五组：部署和数据

16. 唯寻工作台是否继续使用豆包空间的本地 SQLite 和本地运行方式？
17. 如果多人使用，是否已有服务器、账号或组织架构来源？
18. 学生数据是否需要导入现有 Excel？最常用的一张表是什么？
19. 是否有数据保存期限、删除、备份和导出要求？
