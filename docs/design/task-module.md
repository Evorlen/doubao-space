# 任务模块设计

## 1. 文档信息

- 状态：设计初稿
- 适用范围：单用户个人工作台
- 主要场景：日常生活任务、工作任务、较大任务的逐层拆解
- 当前边界：任务模块负责任务本身的组织和管理；日程模块负责任务在日历中的呈现、提醒和时间安排

## 2. 设计目标

任务模块用于帮助用户把生活和工作中的事项组织成清晰的任务树，并持续管理每个任务的期限、优先级和完成情况。

核心目标：

- 支持从大任务向下拆解为多层子任务；
- 保持父子任务之间清晰、可校验的期限关系；
- 让用户能够快速定位当前需要处理的任务；
- 让父任务的整体优先级能够反映未完成后代任务的紧迫程度；
- 为后续日程模块提供可靠的截止时间数据。

## 3. 模块职责

### 3.1 任务模块负责

- 创建、编辑、查看和删除任务；
- 建立任务树和维护父子层级；
- 管理任务标题、描述、附件、链接、标签、截止时间、优先级和完成状态；
- 校验任务层级、截止时间等结构约束；
- 展示任务树、任务详情、搜索结果和筛选结果；
- 提供排序、搜索、筛选、移动和删除等管理能力。

### 3.2 当前不属于任务模块

以下内容暂不在本模块中实现，后续结合日程模块统一设计：

- 截止任务在日历中的具体展示形式；
- 提醒和通知规则；
- 重复任务；
- 执行时间段、开始时间和预计时长；
- 任务之间的独立依赖关系；
- 多用户、负责人和协作权限；
- 除 Excel 导入外的其他批量操作。

## 4. 任务概念

### 4.1 任务是可独立管理的节点

任务树中的每一个节点本身都是一个完整任务，而不仅仅是一个分组容器。父任务和子任务都可以拥有自己的描述、截止时间、优先级和完成状态。

例如：

```text
准备一次旅行
├── 确定目的地
├── 预订酒店
└── 整理行李
```

“准备一次旅行”本身也是需要单独完成的任务；子任务只是对它的拆解。

### 4.2 任务树

- 一个任务最多只能有一个直接父任务；
- 允许存在多个顶层任务；
- 顶层任务不需要挂在一个虚拟的“总任务”下；
- 顶层任务计为第 1 层；
- 任务树最多 5 层，第 5 层不能继续创建子任务；
- 一个任务及其全部后代任务构成一个任务子树。

### 4.3 任务与标签的关系

任务树负责表达任务的拆解关系；标签负责跨任务树进行分类和筛选。两者相互独立。

- 一个任务可以拥有多个自定义标签；
- 标签可以在任务表单中直接创建，也可以在独立标签管理页面中创建；
- 标签不改变任务的父子层级。

## 5. 任务属性

### 5.1 基础属性

| 属性 | 规则 |
| --- | --- |
| 标题 | 必填，作为关键词搜索的唯一内容来源 |
| 父任务 | 可为空；为空时任务为顶层任务 |
| 描述 | 支持富文本 |
| 附件 | 可选 |
| 外部链接 | 可选，可添加多个 |
| 标签 | 可选，可添加多个自定义标签 |
| 截止时间 | 可选，但受任务树期限模式约束，精确到日期和时刻 |
| 优先级 | 必填，默认值为“中” |
| 状态 | 只有“未完成”和“已完成” |

### 5.2 优先级

优先级从高到低为：

1. 紧急
2. 高
3. 中
4. 低

每个任务都保留自己的优先级设置。父任务在界面上显示的最终优先级按以下规则计算：

```text
最终优先级 = max(父任务自身优先级, 所有未完成后代任务中的最高优先级)
```

规则说明：

- 计算范围包括所有层级的未完成后代任务；
- 子任务完成后，不再参与父任务优先级计算；
- 父任务自身优先级不会被修改，只计算最终展示值；
- 界面只显示最终生效的优先级，不额外展示优先级来源。

### 5.3 完成状态

任务只有两种状态：

- 未完成；
- 已完成。

不设置“未开始”“进行中”“暂停”“取消”等中间状态。

## 6. 截止时间模型

### 6.1 时间含义

任务中的时间只表示截止时间，不表示：

- 开始时间；
- 计划执行时间段；
- 预计时长。

截止时间精确到日期和时刻，例如 `2026-09-25 18:00`。

### 6.2 任务树期限模式

任务树必须保持统一的期限模式：

#### 有期限任务树

- 父任务有截止时间时，所有后代任务都必须有截止时间；
- 子任务的截止时间不能晚于任意上级任务的截止时间；
- 子任务可以与父任务使用相同的截止时间，也可以更早。

#### 无期限任务树

- 父任务没有截止时间时，所有后代任务都不能设置截止时间；
- 无期限父任务下不能创建有期限子任务。

### 6.3 不自动修改期限

系统不自动延长、缩短、清除或继承修改其他任务的截止时间。

以下操作均应禁止保存，并明确指出冲突任务：

- 将父任务改得早于已有子任务的截止时间；
- 清除父任务截止时间，但子任务仍有截止时间；
- 给无期限父任务设置截止时间，但子任务仍无截止时间；
- 创建或移动任务后导致子任务期限晚于父任务；
- 其他使任务树期限模式不一致的操作。

### 6.4 创建子任务时的默认值

- 在有期限父任务下创建子任务：子任务默认填入父任务截止时间，用户可以改得更早；
- 在无期限父任务下创建子任务：截止时间字段置灰，并显示“该任务无期限”；
- 如果用户将子任务期限改得晚于父任务，禁止保存。

### 6.5 逾期表现

逾期不是独立任务状态。任务超过截止时间仍未完成时：

- 任务仍保持“未完成”；
- 仅将截止时间显示为红色；
- 不自动移动任务或改变任务状态。

## 7. 完成规则

### 7.1 父任务的完成前置条件

父任务只有在所有后代任务都已完成后，才允许被标记为完成。

子任务全部完成时：

- 父任务不会自动完成；
- 父任务仍显示为未完成；
- 用户必须手动确认完成。

### 7.2 完成操作

所有任务的完成操作都需要二次确认。

当父任务仍有未完成后代时，用户点击完成：

1. 弹出阻止性提示；
2. 列出尚未完成的后代任务；
3. 不允许完成父任务；
4. 引导用户先处理未完成任务。

任务一旦完成：

- 不允许恢复为未完成；
- 不允许修改任务内容和属性；
- 不允许添加子任务；
- 仍可查看或永久删除。

### 7.3 完成任务的显示

- 已完成任务默认在任务树中隐藏；
- 通过顶部工具栏的“显示已完成”开关查看；
- 已完成任务仍保留在原有层级位置；
- 已完成任务不参与父任务的优先级继承计算。

## 8. 任务树操作规则

### 8.1 创建任务

创建任务采用完整表单，并使用大尺寸弹窗，不离开任务树页面。

支持两种入口：

1. 全局“新建任务”
   - 父任务默认为空；
   - 可通过可搜索的任务树选择父任务；
   - 不选择父任务时创建为顶层任务。

2. 父任务详情页中的“添加子任务”
   - 自动带入当前父任务；
   - 父任务关系不可修改。

### 8.2 编辑任务

- 普通任务进入详情页后默认直接可编辑；
- 编辑完成后点击“保存”提交；
- 点击“取消”放弃本次修改；
- 关闭页面或离开页面时，如存在未保存修改，需要提示用户；
- 已完成任务完全只读。

### 8.3 移动任务

任务不支持拖拽调整层级，使用“更多”菜单中的“移动任务”操作。

移动规则：

- 移动父任务时，父任务和全部后代一起移动；
- 可以移动到其他父任务，也可以移动到顶层；
- 不能移动到自身或自己的后代节点下；
- 移动后必须重新校验 5 层深度限制和全部期限规则；
- 发生任何冲突时禁止移动，并明确列出冲突原因；
- 系统不自动调整任务的期限或其他属性。

### 8.4 删除任务

删除父任务时，父任务及全部后代任务一起永久删除。

- 删除前必须二次确认；
- 确认提示应明确说明将删除整个任务子树；
- 删除后不进入回收站；
- 不提供撤销和恢复功能。

### 8.5 Excel 导入子任务

任务节点支持从 Excel 导入子任务。导入入口位于任务树每个节点的“更多”菜单和任务详情页的子任务区域。

- 每一行创建一个当前任务的直系子任务；Excel 不填写父任务和层级；
- 已完成任务和第 5 层任务不能导入；
- 支持 `任务标题`、`导入编号`、`任务描述`、`截止时间`、`优先级`、`标签` 和 `外部链接`；
- `任务标题`必填，优先级为空时默认为“中”；
- 父任务有截止时间时，子任务截止时间必填且不能晚于父任务；父任务无截止时间时，子任务截止时间必须为空；
- 导入编号在当前父任务下用于稳定查重；没有导入编号时，使用任务标题和截止时间查重；
- 导入采用“预览—确认”流程，错误行会阻止整个批次写入，重复行跳过并展示原因；
- 导入任务默认为未完成，附件和富文本格式不通过 Excel 导入。

## 9. 页面与信息架构

### 9.1 任务树页面

任务模块默认打开全宽任务树页面。

页面组成：

- 顶部工具栏：新建任务、搜索、筛选、排序、显示已完成、展开全部、折叠全部；
- 主体区域：任务树；
- 不设置固定的左右侧栏。

任务树默认全部折叠，用户可以：

- 逐个展开节点；
- 一键展开全部；
- 一键折叠全部。

### 9.2 任务节点

任务节点默认显示：

- 任务标题；
- 完成操作；
- 截止时间；
- 最终生效优先级；
- 子任务完成进度；
- 标签。

标签较多时，节点显示前几个标签，超出部分显示为 `+N`；详情页显示全部标签。

每行固定显示“更多”操作菜单，包含：

- 打开详情；
- 添加子任务；
- 移动任务；
- 删除任务。

### 9.3 任务详情页

任务详情页使用独立页面，不使用右侧抽屉。

详情页应包含：

- 完整父级路径，例如“工作 / 项目 A / 撰写方案 / 整理资料”；
- 任务完整属性和富文本描述；
- 附件和外部链接；
- 全部标签；
- 子任务概览；
- 保存和取消操作。

子任务在详情页中只展示概览；需要查看或编辑子任务时，点击进入子任务详情页。

## 10. 排序、搜索和筛选

### 10.1 默认排序

任务树默认按以下顺序排序：

1. 截止时间从近到远；
2. 截止时间相同时，优先级从高到低；
3. 无截止时间的任务排在所有有截止时间任务之后。

用户可以切换排序方式，候选排序包括截止时间、优先级和创建时间。

### 10.2 排序范围

- 树状视图：只对每个父任务下的同级子任务排序，保持树结构；
- 搜索结果：任务以扁平列表展示，并统一排序。

### 10.3 关键词搜索

- 只搜索任务标题；
- 搜索结果为扁平列表；
- 不补充父级节点；
- 默认不搜索已完成任务；
- 不搜索任务描述、标签、附件和外部链接。

### 10.4 条件筛选

支持按以下条件筛选：

- 完成状态；
- 优先级；
- 截止时间；
- 标签。

筛选规则：

- 多个筛选条件之间使用 AND 逻辑；
- 同时选择多个标签时，任务必须同时拥有全部标签；
- 截止时间支持自定义日期和时间范围；
- 只使用筛选条件、不输入关键词时，结果保持树状结构，只隐藏不符合条件的任务；
- 已完成任务默认仍受“显示已完成”开关控制。

## 11. 典型操作流程

### 11.1 创建顶层任务

1. 点击顶部“新建任务”；
2. 打开大尺寸创建弹窗；
3. 填写标题；
4. 父任务保持为空；
5. 选择优先级，默认值为“中”；
6. 可选填写截止时间、描述、标签、附件和链接；
7. 保存后任务出现在顶层任务列表中。

### 11.2 创建子任务

1. 从父任务详情页点击“添加子任务”，或从全局新建表单选择父任务；
2. 系统校验当前父任务是否已经是第 5 层；
3. 有期限父任务：默认填入父任务截止时间；
4. 无期限父任务：截止时间字段置灰；
5. 填写任务内容并保存；
6. 新任务加入父任务的子任务列表。

### 11.3 完成任务

1. 点击任务完成操作；
2. 弹出二次确认；
3. 如果任务有未完成后代，显示阻止提示和未完成任务列表；
4. 如果所有后代已完成，确认后将任务标记为已完成；
5. 任务完成后不可恢复，且默认隐藏。

### 11.4 修改期限

1. 用户编辑任务截止时间；
2. 系统校验当前任务树的期限模式和上下级期限关系；
3. 如果产生冲突，禁止保存；
4. 错误提示列出受影响的子任务或后代任务；
5. 用户调整规划后重新保存。

### 11.5 移动任务

1. 在任务行的“更多”菜单中选择“移动任务”；
2. 在任务树选择新的父任务或顶层位置；
3. 系统校验是否形成循环、是否超过 5 层、是否违反期限规则；
4. 校验通过后，整个任务子树一起移动；
5. 校验失败时禁止移动并展示原因。

## 12. 关键校验提示建议

提示文案应说明问题和下一步动作，不自动替用户修改计划。

示例：

- “无法保存：子任务‘制作附件’的截止时间晚于父任务‘写完项目方案’。”
- “无法设置为无期限：以下子任务仍设置了截止时间：……。”
- “无法设置截止时间：该父任务下存在无期限子任务，请先为它们设置期限。”
- “无法移动：移动后任务将超过第 5 层。”
- “无法移动：移动后将产生期限冲突，请先调整任务规划。”
- “该父任务仍有未完成子任务，请先完成以下任务：……。”
- “删除后将永久删除当前任务及其全部子任务，且无法恢复。”
- “已完成任务不可编辑或恢复为未完成。”

## 13. 概念数据模型

以下是面向设计和开发协作的概念字段，不限定最终数据库实现：

```text
Task
├── id
├── parent_id              可为空，指向直接父任务
├── depth                  由树结构计算或维护，范围 1～5
├── title
├── description            富文本内容
├── due_at                 可为空，精确到日期和时刻
├── priority               任务自身设置：urgent/high/medium/low
├── effective_priority     根据后代任务动态计算的展示值
├── status                 incomplete/complete
├── created_at
└── updated_at
```

关联数据：

- `task_tags`：任务与自定义标签的多对多关系；
- `task_attachments`：任务附件；
- `task_links`：任务外部链接。

实现时需要特别注意：

- `effective_priority` 不应覆盖任务自身的 `priority`；
- 删除任务需要递归删除整个后代子树及其关联内容；
- 已完成任务的编辑接口和创建子任务接口应在后端再次校验，而不仅依赖前端禁用；
- 截止时间、层级深度和父子关系规则需要前后端共同校验。
